# 引言

这是关于 RAG 知识库系统的一份测试文档。本文档用于验证 MinerU 集成和 Markdown 切片器的正确性。

## 第一章 研究背景

随着大语言模型（LLM）的快速发展，检索增强生成（RAG）技术成为解决 LLM 幻觉问题的关键方案之一。

### 1.1 RAG 的核心流程

RAG 系统通常包含以下核心步骤：

1. 文档摄入：将原始文档解析为结构化文本
2. 文本切片：按语义边界将长文档切分为合适的 chunk
3. 向量化：使用 Embedding 模型将文本转换为向量
4. 存储：将向量存入向量数据库（如 PGVector）
5. 检索：根据用户查询召回相关 chunk
6. 生成：将召回内容作为上下文，由 LLM 生成回答

### 1.2 切片策略对比

| 策略 | 优点 | 缺点 |
|------|------|------|
| 固定长度切分 | 简单快速 | 破坏语义边界 |
| 标题感知切分 | 保留结构 | 需要结构化输入 |
| 语义感知切分 | 最精确 | 需要 Embedding 模型 |

## 第二章 实现细节

### 2.1 MinerU 解析

MinerU 是一个开源的文档解析引擎，能够将 PDF 转换为带标题层级的 Markdown。

其 pipeline 后端特点：
- 支持纯 CPU 运行
- 自动去除页眉页脚
- 表格转换为 HTML 格式
- 公式转换为 LaTeX

### 2.2 Markdown 切片器

Markdown 切片器采用两级切分策略：
1. 第一级：按标题层级（# / ## / ###）粗分大块
2. 第二级：在每块内部用 RecursiveCharacterTextSplitter 按 chunkSize 切分

每个最终 chunk 都会携带 headingPath 元数据，便于检索时恢复章节上下文。

## 第三章 性能评估

在 OmniDocBench v1.6 上，MinerU pipeline 后端取得了 86.2 的分数，超过了上一代 VLM 模型。

### 3.1 实验结果

| 方法 | 准确率 | 推理时间 |
|------|--------|----------|
| pipeline | 86.2 | 0.8s/page |
| vlm-engine | 95.4 | 3.2s/page |
| hybrid-engine | 95.3 | 2.1s/page |

## 结论

MinerU + Markdown 切片器的组合为 RAG 系统提供了高质量的文档预处理方案，相比传统的 pdf-parse + 固定长度切分，显著提升了检索召回率。
